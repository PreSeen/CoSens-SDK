# 中文售后退款审核：Recipe 本身迭代与交付质量

执行器固定为 GPT-6 Luna。任务为仿真售后资料的退款核算、正式审批边界和客户回复。多版本政策、订单、优惠券、审批草稿和历史退款流水都包含在公开输入中；不涉及外部法律建议或真实退款。

这是 Recipe 方法优化实验：同一模型、工具、预算、独立业务检查和每题冻结快照，只改变不可变版本 Recipe 的方法槽位。没有候选执行路线重排，没有为了提速修改数据访问方法。

- 初始 v1 是正常的“读资料、核算、证据审核、交付并自查”方法，未预置错误。
- 训练：2 个不同业务工单，每个 2 次实际执行，保留所有输出和检查结果。优化器仅拿到训练任务、实际输出、失败反馈及当前 Recipe，生成 2 份最小方法变更，不提供筛选或确认材料。
- 筛选：另外 2 个工单，同一旧版与 2 个候选各实际执行。
- 确认：4 个新工单，对旧版与筛选出的候选成对实际执行。预先固定平均质量提升至少 3 个百分点、区间下界大于 0、无关键业务检查退化、无已成功任务退化。禁止用单纯提速路径通过发布。
- 发布：通过服务器的独立验证结果后，调用管理员版本校验发布流程；不通过普通导入接口绕过门槛。自定义初始 Bundle 接口只能初始化空任务族。
- 应用：v2 发布后，再用它真实执行与首次相同的原任务。这个重放不是留出证明；留出效果看 4 个确认工单。

独立参考实现用整数分和最大余数分摊计算期望值，检查政策生效日、审批和申请区别、累计退款取整、已到账流水去重、运费、逐行证据、隐私及中文回复。措辞接受等义表达；待批说明检查每个待批商品的实质内容。规则在确认执行前冻结，不用模型自评当成业务验收。

工件路径发现是执行器责任。模型合法保存到唯一子目录时，适配器只复制原文件字节并记录来源哈希；不能把未找到工件当作低业务质量。前期工件路径适配、候选 binding 名校验和过严措辞检查的失效尝试都保留，排除在最终质量证据之外，未用于选择最终确认结果。

初始公开材料与内部参考规格在 input-lock.json 中冻结。服务器托管的每次真实执行保存完整记录、文件字节哈希及可观察工具日志；公开前端显示质量检查、Recipe 变更和可读文档，不展示模型内部思维或全量后台 JSON。读取评测工件需要同一 Case 身份与正式确认记录，文件哈希变化会拒绝展示。

这是合成业务工单的小样本、每确认工单每版本一次的演示，不代表生产泛化、通用模型能力或对随机性的可靠估计。所有运行成本、模型耗时和失败记录保留。
