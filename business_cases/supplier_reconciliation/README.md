# 中文供应商月结对账：一次反馈后的 RSI 选路改善

这是 GPT-6 Luna 通过本地 Codex、RSI MCP 和插件执行的中文财务核查任务。数据是确定性生成的仿真账套：80,000 张发票、81,631 条付款记录、18 家待核供应商；不代表任何企业真实账务。

两次独立 Codex 会话使用同一数据、业务规则、固定候选及先验和 seed Recipe。第一次实际执行后，操作员独立核对全部输出，并把计算正确性及预设 2 秒目标的实测反馈经 RSI 写回 Memory。第二次准备时冻结新经验水位，RSI 检索这条经验，重新排列候选。没有额外校准 Run，也不让执行器直接操作 Memory。

候选为逐供应商 CSV 扫描或本次从零创建 SQLite 索引后批量核对。首次同分选择第一项，是提前披露的确定性策略；不代表自由策略 Codex 会选它。CSV 路线的真实负反馈可以降低其分数，未尝试的 SQLite 路线仍是中性先验，不能宣称已被证明更优。两次都保留真实结果；若结果不改善就报告未改善。

`requirements.md` 固定业务约束、2 秒演示目标和奖励；`protocol.json` 固定候选、观察和环境；`input-lock.json` 固定数据与脚本哈希。`oracle.py` 独立使用字典账本逐行核对，既不导入执行引擎，也不依赖模型的自报验收。`operator.py` 验证冻结输入、本地三轮完整 CSV 与已提交测量工件相符，再用独立管理凭证登记 verified；凭证不进入模型会话。

计时为三轮新进程内完整数据核对计算的中位数，包括每轮 CSV 读取、数据库冷建/导入/索引、核对及异常清单输出。数据库不跨轮复用。模型生成中文报告、MCP 往返、输入哈希及独立参考核对不在计算计时内；工具总 wall time 在测量中另列。不是完整模型任务时延对照。

此实验为同一任务的在线反馈后重放，不是留出集泛化；没有估计模型随机性和显著性；不宣称中文建议质量、真实财务收益、模型权重或 Recipe 改善。两条路线使用预先固定的工具，展示 RSI 学会避开该负载下已经证实成本过高的访问路线。

产物在 `work/baseline` 与 `work/after`，包含中文报告、异常清单、三轮测量、核验记录、Run 引用与独立评估回执。前端 Case 中可以逐步查看真实输入、选路、产物、经验来源和写回，并下载该次实际冻结 Recipe。

对应工程改进：rerank v2 让未尝试候选使用明确的中性 reward prior，修复仅有一条已验证负反馈时 advantage 自相抵消的问题。已冻结 v1 策略继续保持原语义；pending、权限范围、经验兼容性和独立任务去重规则不变。
